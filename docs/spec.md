# GM Helper — спецификация

Десктопное приложение для game master'а: библиотека артов и токенов, быстрые тактические баттлмапы, граф отношений персонажей, хронология сюжета и фоновая музыка с простым редактором. Работает офлайн под Windows, данные хранятся локально.

## 1. Общие решения

| Вопрос            | Решение                                                                                                                                                 |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Платформа         | Десктоп, Windows (основная цель). Tauri 2                                                                                                               |
| Стек              | Tauri 2 + React + TypeScript (Vite). Rust-часть минимальна: плагины Tauri (fs, dialog, sql), без собственной бизнес-логики, если её можно сделать на TS |
| Язык интерфейса   | Русский. Код, идентификаторы и комментарии — на английском                                                                                              |
| Данные приложения | Одна SQLite-база в каталоге данных приложения (`%APPDATA%/com.gmhelper.app/gm-helper.db`)                                                               |
| Арты              | Обычные файлы в папке-библиотеке, которую выбирает пользователь. В БД — только индекс и метаданные                                                      |
| Кампании          | Несколько кампаний. Библиотека артов общая для всех. Персонажи, граф отношений, хронология и баттлмапы принадлежат кампании                             |
| Системы           | Кампания привязана к игровой системе (папке верхнего уровня библиотеки). Это влияет на приоритет в поиске артов                                         |

### 1.1. Основные сущности

- **Система** (`System`) — папка верхнего уровня библиотеки (например `D&D 5e`, `Pathfinder 2e`, `Warhammer FRP`).
- **Группа** (`Group`) — папка второго уровня: группа существ или фракция (`Нежить`, `Гильдия воров`).
- **Арт** (`Art`) — файл изображения внутри группы.
- **Токен** (`Token`) — круглое PNG-изображение, сделанное из арта. У арта может быть несколько токенов. У токена ровно один исходный арт.
- **Кампания** (`Campaign`) — название, система, описание, дата создания.
- **Персонаж** (`Character`) — НИП или персонаж игрока внутри кампании.
- **Фракция** (`Faction`) — группа персонажей внутри кампании (для графа отношений). Не путать с папкой-группой библиотеки, хотя её можно создать по этой папке.
- **Отношение** (`Relation`) — направленная связь между персонажами и/или фракциями.
- **Событие** (`Event`) — точка на хронологии сюжета.
- **Баттлмап** (`Battlemap`) — сетка клеток с типами и регионами.
- **Трек** (`Track`) — аудиофайл в папке музыки. **Категория** и **подборка** — папки первого и второго уровня.

### 1.2. Общий интерфейс

- Левая панель навигации: Библиотека · Баттлмапы · Отношения · Хронология · Музыка · Настройки. Под ней мини-плеер (§6.3).
- Тема оформления: как в системе, светлая или тёмная. Переключается в настройках и кнопкой на боковой панели, сохраняется между запусками. Цвета содержимого (типы клеток, фракции, типы связей) от темы не зависят.
- Сверху выбор активной кампании. Модули, которые зависят от кампании, показывают данные только активной кампании.
- Библиотека не зависит от кампании. Фильтр по системе активной кампании включён по умолчанию, его можно снять.
- Undo/redo (Ctrl+Z / Ctrl+Y) во всех редакторах: баттлмап, граф, хронология, редактор музыки.
- Автосохранение изменений. Явная кнопка «Сохранить» не нужна.

## 2. Библиотека артов

### 2.1. Структура на диске

```
<корень библиотеки>/
  D&D 5e/
    Нежить/
      lich.png
      skeleton-archer.webp
      _tokens/
        lich.token-1.png
        lich.token-2.png
        skeleton-archer.token-1.png
    Гильдия воров/
      ...
  Pathfinder 2e/
    ...
```

- Строго три уровня: `Система / Группа / файл арта`. Файлы на уровне системы или корня показываются в разделе «Не разобрано», их можно перенести в группу.
- Вложенные папки внутри группы не поддерживаются в MVP: их содержимое попадает в «Не разобрано».
- Токены лежат в подпапке `_tokens` той же группы, чтобы их было видно в проводнике и можно было перетащить в VTT.
- Поддерживаемые форматы артов: PNG, JPG/JPEG, WEBP. GIF и SVG — нет.
- Папки с именем, которое начинается с `_` или `.`, не считаются группами.

### 2.2. Индекс и синхронизация

- В БД для каждого арта хранится: путь относительно корня библиотеки, система, группа, имя (по имени файла без расширения), размер и mtime файла, хэш содержимого, размеры изображения, пользовательские теги и отображаемое имя (если оно отличается от имени файла).
- Пути хранятся относительно корня, поэтому корень можно перенести, указав новый путь в настройках.
- Сканирование при запуске и по кнопке «Обновить». Пока приложение открыто, за папкой следит watcher и обновляет индекс.
- Если файл переименовали или перенесли вне приложения, запись и связи с токенами восстанавливаются по хэшу содержимого.
- Если файл удалили вне приложения, запись помечается «файл отсутствует». Связи не удаляются, пока пользователь сам не очистит такие записи: по одной в панели арта или все сразу кнопкой «Очистить список» в разделе «Отсутствующие» (с подтверждением; файлы токенов этих артов уходят в корзину, портреты персонажей показывают заглушку).
- Миниатюры (≈256 px) генерируются и кэшируются в каталоге данных приложения, не в библиотеке.

### 2.3. Операции

- Просмотр: дерево Система → Группа слева, сетка миниатюр справа, просмотр арта в полный размер.
- Создание, переименование и удаление систем и групп (это реальные папки). Удаляется только пустая папка, иначе сначала нужно подтверждение со списком файлов.
- Импорт артов: перетащить файлы в окно или в группу. Файлы **копируются** в выбранную группу. При совпадении имени предлагается переименовать.
- Перемещение арта между группами (вместе с его токенами).
- Переименование арта. Токены переименовываются вместе с ним.
- Удаление арта — только с подтверждением и через корзину Windows, если это возможно.
- Теги и отображаемое имя для арта.

### 2.4. Поиск

- Одна строка поиска по имени файла, отображаемому имени и тегам.
- Без учёта регистра, `ё` = `е`, поиск по подстроке плюс нечёткое совпадение (опечатки, порядок слов).
- Фильтры: система, группа, «только с токенами» / «только без токенов».
- Результаты появляются по мере ввода. Целевое время — меньше 100 мс на библиотеке из 10 000 артов.
- Этот же поиск используется в окне выбора арта для персонажа (раздел 4).

### 2.5. Токены

- Редактор токена открывается из карточки арта: «Создать токен».
- Круглая маска поверх арта, арт можно двигать мышью и масштабировать колесом или слайдером, чтобы в круг попало нужное (например лицо).
- Размер выходного PNG: 256 / 512 (по умолчанию) / 1024 px. Вне круга — прозрачный фон.
- Параметры кадрирования (центр, масштаб, размер) сохраняются в БД, поэтому токен можно открыть и поправить. Файл токена при этом перезаписывается.
- Связь арт → токены: в карточке арта виден список его токенов. В карточке токена есть ссылка на исходный арт. В сетке библиотеки у арта с токенами есть значок.
- Токены создаются, просматриваются и удаляются только через арт. Отдельного раздела «Токены» нет.
- Токен можно скопировать в буфер обмена или открыть его папку в проводнике, чтобы перетащить в VTT.

## 3. Генератор баттлмапов

Это не художественный генератор, а быстрая схема тактической карты: сетка, типы клеток, регионы.

### 3.1. Карта

- Размер задаётся в клетках: ширина × высота, от 5×5 до 200×200. Размер можно изменить потом (обрезать или добавить клетки с любой стороны).
- В редакторе клетка всегда 24×24 px при масштабе 100%. Масштаб вида меняется (зум), сама модель — в клетках.
- Карта принадлежит кампании и имеет название и описание.
- Создание: пустая карта (все клетки «Пол») или с заполненной стеной по периметру.

### 3.2. Типы клеток

Встроенный набор (нельзя удалить, можно поменять цвет):

| Тип                        | Обозначение              | Блокирует движение | Блокирует обзор      |
| -------------------------- | ------------------------ | ------------------ | -------------------- |
| Пол / открытое место       | светлый                  | нет                | нет                  |
| Стена                      | тёмный                   | да                 | да                   |
| Проход / дверь             | коричневый, значок двери | нет                | нет (открытая дверь) |
| Укрытие (половинное)       | штриховка                | нет                | частично             |
| Укрытие (полное)           | плотная штриховка        | да                 | да                   |
| Труднопроходимая местность | точки                    | нет (стоит дороже) | нет                  |
| Объект                     | значок квадрата          | да                 | нет                  |
| Лестница                   | значок ступеней          | нет                | нет                  |
| Вода                       | синий                    | нет                | нет                  |
| Провал / яма               | чёрный с крестом         | да                 | нет                  |

Свои типы на уровне приложения (доступны во всех кампаниях): название, цвет, обозначение (буква, значок из набора или своя картинка), флаги «блокирует движение» и «блокирует обзор», комментарий (например, правила или урон: «2d6 огнём за ход»). Комментарий виден в подсказке палитры редактора и в легенде экспорта. Флаги нужны для легенды и подсказок, правила игры приложение не считает. Свой тип можно создать и в настройках, и прямо из палитры редактора.

Своя картинка выбирается из файла на диске или из библиотеки артов и хранится в БД копией, уменьшенной до 256 px по большей стороне. Поэтому обозначение не ломается, если исходный файл переместить или удалить.

### 3.3. Инструменты редактора

- Кисть: красит клетку выбранным типом. Можно протягивать мышью.
- Прямоугольник: залить прямоугольную область.
- Заливка: заменить связную область одного типа.
- Выделение: клик, Shift+клик (добавить), Ctrl+клик (переключить), рамка мышью. С выделением можно: назначить тип, создать регион, очистить.
- Ластик: вернуть тип «Пол».
- Отмена и повтор действий.

### 3.4. Области (регионы)

- Область (в коде — регион) — несколько клеток, объединённых одним свойством: название, необязательный тип клеток, необязательная заметка. Примеры: «Коридор» (5 клеток в линию), «Большое укрытие» (2 клетки в ширину), «Алтарь».
- Регион создаётся из текущего выделения. Клетки региона не обязаны быть смежными, но предупреждение показывается, если они несвязны.
- Тип области, если он задан, применяется ко всем её клеткам и перекрывает их собственный тип. Новая область создаётся без типа: клетки сохраняют свои типы, область только отмечает место.
- Клетка входит не больше чем в один регион. При добавлении клетки в новый регион она убирается из старого.
- На карте регион обведён общим контуром, в центре подпись (её можно скрыть).
- Список регионов на боковой панели: выбор подсвечивает регион на карте, можно переименовать, сменить тип, добавить или убрать клетки, удалить (клетки возвращают свой тип).

### 3.5. Объекты

- Объект — обозначение размером W×H клеток (от 1×1 до 10×10): например «Стол» 2×1, «Алтарь» 3×3. У объекта есть название, картинка (своя, как у типов клеток) или буква / значок, цвет фона и флаги «блокирует движение» и «блокирует обзор».
- Справочник объектов общий для всех кампаний (как типы клеток). Его можно править в настройках и прямо из редактора.
- Инструмент «Указатель»: клик по объекту выделяет его (Shift — добавить, Ctrl — переключить), объект можно перетащить; перетаскивание по пустому месту сдвигает карту. Клетки этим инструментом не меняются.
- Инструмент «Объект»: выбрать объект в палитре и кликнуть по карте — объект встаёт левым верхним углом в клетку под курсором (если не помещается у края, сдвигается внутрь карты). Клавиша R поворачивает его на 90° перед установкой.
- Поставленный объект можно выделить кликом инструментом «Выделение» (Shift — добавить, Ctrl — переключить), перетащить, повернуть (R, вокруг левого верхнего угла), удалить (Delete). Объекты рисуются поверх клеток и не меняют их тип. Объекты могут перекрываться.
- Объекты входят в экспорт PNG и в легенду.
- Если объект удалить из справочника, его экземпляры на картах показываются серой заглушкой «?», пока их не удалят.
- Файл `.gmmap.json` (версия 2) содержит используемые картой свои типы и объекты вместе с картинками, поэтому карта выглядит так же на другом ПК.

### 3.6. Библиотека карт

- Экран «Баттлмапы» показывает карты кампании сеткой карточек с превью (превью обновляется при автосохранении карты). Есть поиск по названию и тегам (с теми же правилами, что в библиотеке артов: регистр, `ё`/`е`, нечёткость).
- У карты есть теги.
- Шаблоны — общая для всех кампаний библиотека карт. «Сохранить как шаблон» копирует карту в библиотеку шаблонов. «Новая карта → из шаблона» копирует шаблон в кампанию. Шаблон открывается и редактируется в том же редакторе, у шаблонов тоже есть теги и поиск.

### 3.7. Сохранение и экспорт

- Карта хранится в БД как JSON (размер, массив типов клеток, регионы, версия формата). Можно экспортировать и импортировать карту файлом `.gmmap.json`.
- Экспорт PNG для Roll20 и Owlbear Rodeo:
  - размер клетки: 24 / 70 (по умолчанию, стандарт Roll20) / 100 / 140 px;
  - опции: сетка вкл/выкл, подписи регионов, легенда (отдельным PNG или полосой справа);
  - в имени файла указан размер в клетках (`Склеп_30x20_70px.png`), чтобы было легко задать сетку в VTT.
- Экспорт в форматы с «умными» стенами (Foundry, UVTT) в MVP не входит.

## 4. Граф отношений

### 4.1. Персонажи

- Персонаж кампании: имя, вид (НИП / персонаж игрока), имя игрока (для ПИ), роль или краткое описание, статус (жив / мёртв / пропал / неизвестно), описание, мотивация, секреты (только для мастера), теги, фракции.
- Арт персонажа: кнопка «Выбрать арт» открывает поиск по библиотеке (раздел 2.4). Сначала показываются арты системы кампании, есть переключатель «вся библиотека». Можно выбрать сам арт или один из его токенов. На графе показывается токен, если он есть, иначе арт, обрезанный в круг.
- Быстрое создание персонажа из арта: в библиотеке «Создать персонажа» → имя берётся из имени арта.
- Если файл арта пропал, у персонажа показывается заглушка и предупреждение.

### 4.2. Фракции

- Фракция: название, цвет, описание, необязательный арт или эмблема.
- На графе фракция показана как рамка-группа вокруг своих персонажей. Персонаж может быть в нескольких фракциях. Тогда он отображается в основной фракции, а другие показаны значками.
- Фракции тоже могут быть концами связей (например «Гильдия воров» → «враждует» → «Городская стража»).

### 4.3. Связи

- Связь направленная: от A к B. «A ненавидит B» и «B ненавидит A» — разные связи. Флаг «взаимная» рисует одну линию со стрелками на обоих концах.
- Тип связи из настраиваемого списка с цветом и стилем линии. По умолчанию: союз, дружба, вражда, соперничество, любовь, родство, служба/подчинение, долг, страх, неизвестно.
- У связи есть подпись (короткая, видна на графе) и заметка (длинная, в боковой панели).
- Между одной парой может быть несколько связей разных типов.
- Связь персонажа с его основной фракцией (той, в рамке которой он нарисован) стрелкой не рисуется. Такие отношения показываются подписями под персонажем, когда он выбран (клик по узлу).

### 4.4. Работа с графом

- Свободное полотно: узлы перетаскиваются, позиции сохраняются. Зум, панорамирование, мини-карта.
- Создание связи: протянуть линию от узла к узлу, затем выбрать тип.
- Клик по узлу или связи открывает боковую панель с карточкой.
- Поиск персонажа по имени с центрированием на нём.
- Фильтры: по типу связи, по фракции, скрыть мёртвых, только ПИ и их прямые связи.
- Автоматическая раскладка по кнопке (не при каждом изменении).
- Экспорт графа в PNG.

## 5. Хронология сюжета

### 5.1. Модель

- **Дорожки** (колонки):
  - «Основной сюжет» — всегда есть;
  - «Побочные квесты» — одна общая или несколько именованных;
  - «Личный квест: <имя ПИ>» — необязательная дорожка, её можно завести для любого персонажа игрока кампании (название следует за именем персонажа).
  - Можно добавлять свои дорожки, менять их порядок и скрывать. Свою дорожку или личный квест можно удалить, их события переходят в «Основной сюжет».
- **Ось времени** идёт сверху вниз по сессиям: «Сессия 1, 2, …», в конце — «Будущее» (запланировано, сессии ещё нет). Сессии добавляются по одной в конец; последнюю можно убрать, её события переходят в «Будущее».
- **Порядок внутри сессии** общий для всех дорожек: каждое событие занимает свою строку, так что сверху вниз читается порядок истории.
- **Отметки игрового времени** — свободный текст («Зима 1492», «3-й день месяца Урожая») с уровнем: крупная (эпоха, год), средняя (месяц), мелкая (день). Отметка стоит между событиями в общем порядке сессии. Календарь мира не нужен.
- **Событие**: название, описание, дорожка, сессия, порядок внутри сессии, игровая дата (свободный текст, только подпись), важность (основное / второстепенное), статус (запланировано / произошло / провалено / отменено), связанные персонажи (из раздела 4), теги.
- **Связи событий**: направленные стрелки «причина → следствие», в том числе между дорожками (например, личный квест вызывает событие основного сюжета).

### 5.2. Отображение и работа

- Таймлайн во всю ширину экрана: слева скобки сессий и блок «Будущее», в центре колонки дорожек с карточками событий, справа ось игрового времени с отметками. Стрелки связей поверх.
- Лента ограничена своими краями: за пределами колонок и сессий ничего нет. Колёсико прокручивает вверх-вниз, Shift + колёсико и перетаскивание фона — также вбок, если лента шире экрана.
- Колонки всегда делят ширину экрана; вбок лента листается, только если дорожек так много, что колонки не помещаются. Ctrl + колёсико масштабирует только по вертикали: приближение увеличивает карточки и текст в них, раздвигает события и показывает мелкие отметки; отдаление сжимает ленту (карточки в одну строку или полоской, видны только крупные отметки). Место под курсором при масштабе остаётся на месте.
- Названия дорожек сверху, скобки сессий слева и ось времени справа закреплены при прокрутке.
- Статус виден по стилю: произошло — сплошная карточка, запланировано — пунктир, провалено или отменено — приглушённая и зачёркнутая.
- Перетаскивание карточки между сессиями, дорожками и местами в порядке; отметки времени перетаскиваются вдоль оси. Двойной щелчок в колонке дорожки создаёт событие в этом месте, у оси времени — отметку.
- Клик по событию или отметке открывает боковую панель. Из панели события можно перейти к связанным персонажам на графе отношений.
- В карточке персонажа (раздел 4) есть список событий с его участием.
- Фильтры: по дорожке, статусу, персонажу, тегу. Кнопка «Что уже произошло» скрывает всё запланированное.
- Текущая сессия выделена: цветная скобка и линия над ней.
- Экспорт в PNG.

## 6. Музыка

Раздел «Музыка» — каталог фоновой музыки и звуков с плеером (вкладка «Слушать») и простой многодорожечный редактор (вкладка «Редактировать»). Музыка общая для всех кампаний, как и арты.

### 6.1. Структура на диске

```
<папка музыки>/
  Бой/
    Эпичные/
      dragon-fight.mp3
    Засада/
      ...
  Атмосфера/
    Таверна/
      tavern-crowd.ogg
    Дождь/
      ...
```

- Отдельная папка, её выбирают в настройках (при первом открытии раздела — предложение выбрать). Без неё остальные разделы работают как раньше.
- Два уровня: `Категория / Подборка / файл`. Файлы выше подборки попадают в «Не разобрано», как в библиотеке артов. Папки на `_` и `.` не считаются подборками.
- Форматы: MP3, OGG, WAV, FLAC, M4A (то, что умеет воспроизводить WebView2).

### 6.2. Каталог

- Индекс в БД, как у артов (§2.2): относительный путь, категория, подборка, имя, размер, mtime, хэш, длительность, теги, отображаемое имя. Длительность определяется при первом чтении файла.
- Сканирование при открытии раздела и по кнопке «Обновить», watcher, пока приложение открыто. Переименованные вне приложения файлы находятся по хэшу и сохраняют теги, удалённые помечаются «файл отсутствует». Их записи очищаются по одной или все сразу, как в библиотеке артов (§2.2).
- Операции как в библиотеке артов (§2.3): создание, переименование и удаление категорий и подборок, импорт перетаскиванием (копирование), перемещение и переименование трека, удаление через корзину с подтверждением, теги и отображаемое имя.
- Поиск по имени, отображаемому имени и тегам с теми же правилами (§2.4), фильтр по категории и подборке. Теги удобно использовать для настроения: «таверна», «погоня», «грусть».
- Вид: дерево Категория → Подборка слева, список треков (название, длительность, теги) справа, карточка трека сбоку. Список виртуализирован (тысячи треков).

### 6.3. Плеер

- Двойной щелчок по треку запускает его; очередь — текущий список (подборка или результаты поиска) в его порядке.
- Управление: воспроизведение / пауза, предыдущий / следующий, перемотка по шкале, громкость, перемешивание, повтор (нет / весь список / один трек).
- Плавный переход между треками (0–10 с, по умолчанию 3 с; 0 — без перехода). Настройка в разделе.
- Мини-плеер внизу боковой панели виден на всех экранах: название трека, пауза, следующий, громкость, шкала. Музыка не прерывается при переходе между разделами и при смене кампании.
- Пробел в разделе «Музыка» — пауза / воспроизведение (если курсор не в поле ввода).
- Громкость, повтор, перемешивание и длительность перехода сохраняются между запусками. Очередь и позиция — нет.

### 6.4. Редактор

Вкладка «Редактировать» — минимальный многодорожечный редактор, чтобы собрать фон из нескольких треков (например, музыка + дождь + шум таверны) или подрезать и зациклить трек.

- **Источники:** до трёх треков из каталога («Добавить в редактор» в карточке трека или выбор в редакторе). Для каждого показывается волна; на ней выделяется фрагмент мышью.
- **Дорожки:** три дорожки, они звучат одновременно и смешиваются. У дорожки — громкость и «без звука».
- **Клипы:** выделенный фрагмент источника кладётся на дорожку как клип. Клип можно:
  - передвинуть по времени и перенести на другую дорожку;
  - обрезать с начала или конца (перетаскиванием края);
  - разрезать в позиции курсора воспроизведения;
  - дублировать (копия встаёт сразу после оригинала);
  - копировать и вставить на другую дорожку в позицию курсора (Ctrl+C / Ctrl+V);
  - удалить.
- Клипы на одной дорожке не накладываются: при перемещении клип встаёт вплотную к соседу.
- Прослушивание результата с любой позиции, шкала времени с масштабом, привязка к краям клипов.
- Undo/redo (Ctrl+Z / Ctrl+Y).
- **Сохранение:** результат сводится и кодируется в MP3 (192 кбит/с) и сохраняется **новым** файлом в папку музыки — пользователь выбирает подборку и имя. Исходные файлы не меняются, существующий файл не перезаписывается. Новый трек сразу появляется в каталоге.
- Проект редактора живёт, пока открыто приложение (переключение разделов его не теряет). Сохранение проекта в файл не входит в MVP.

## 7. Настройки и данные

- Путь к корню библиотеки. При первом запуске его нужно выбрать.
- Путь к папке музыки (необязательно).
- Тема оформления.
- Управление кампаниями: создать, переименовать, сменить систему, архивировать, удалить (с подтверждением).
- Справочники: типы клеток, объекты баттлмапов, типы связей.
- Резервная копия: экспорт кампании (персонажи, фракции, связи и используемые ими свои типы связей, хронология, карты вместе с используемыми в них своими типами клеток и объектами, ссылки на арты по относительным путям и хэшам, записи токенов) в один JSON-файл (`<кампания> <дата>.gmcampaign.json`, поле `version`) и импорт обратно. Сами арты в копию не входят: они уже лежат файлами в библиотеке. Шаблоны карт общие и в копию кампании не входят.
  - Импорт всегда создаёт новую кампанию с новыми id (копию можно импортировать рядом с оригиналом), если имя занято — с пометкой «(импорт)». Новая кампания становится активной.
  - Арты ищутся в библиотеке по пути, затем по хэшу содержимого. Не найденные перечисляются в отчёте, их портреты показывают заглушку. Токен восстанавливается, если его PNG есть в библиотеке.
  - Свои типы связей, клеток и объекты сопоставляются по id: недостающие добавляются, существующие не меняются.
- Схема БД версионируется миграциями. Перед миграцией создаётся копия файла БД.

## 8. Нефункциональные требования

- Работа полностью офлайн, без аккаунтов и сети.
- Библиотека до 10 000 артов работает без заметных задержек: виртуализированная сетка миниатюр, ленивая генерация миниатюр.
- Баттлмап 200×200 рисуется и редактируется плавно (Canvas, а не DOM-элемент на каждую клетку).
- Приложение никогда не удаляет и не перезаписывает файлы артов пользователя без явного подтверждения. Исключение — файлы токенов, которые оно само создало.
- Если данных нет или файл пропал, интерфейс не ломается, а показывает понятное состояние.

## 9. Вне рамок MVP (возможно позже)

- Рамка токена (цвет и толщина), размеры токенов в клетках (Large / Huge).
- Пакетное создание токенов для целой папки с автоцентрированием.
- Экспорт баттлмапов в Foundry VTT / Universal VTT со стенами и дверями.
- Цветные или художественные баттлмапы, генерация карт по шаблонам.
- Синхронизация между устройствами, совместная работа, доступ для игроков.
- Вложенные папки глубже трёх уровней в библиотеке.
- macOS и Linux (Tauri это позволяет, но тестируется только Windows).
